# Claude Design 프롬프트 — 웨딩페어 랜딩 & 신청자 관리

근거: [design-brief.md](design-brief.md)

```text
목표:
웨딩페어 방문 신청을 받는 웹사이트의 화면을 디자인해 주세요. 예비 신랑신부가 광고를 보고 들어와
박람회 정보를 확인한 뒤 이탈 없이 참가 신청을 마치게 하는 것이 목적입니다. 운영자가 신청 현황을
한눈에 보는 관리자 현황판 한 장도 함께 필요합니다.

대상:
- 방문자: 웨딩페어 방문을 고려하는 예비 신랑신부. 회원가입 없이 신청합니다.
- 관리자: 운영자 1인. Payload CMS 관리자 화면 안에서 현황판을 봅니다.

브랜드:
- 이름: "들꽃 웨딩페어" (가칭). 화면에는 [가칭] 표시를 붙여 주세요.
- 로고: 글자 로고(워드마크). 제목 글꼴 600 굵기, 색은 primary. 장식이 필요하면 선으로 그린 잎 하나만.
  헤더 로고 높이는 PC 32px, 모바일 28px.
- 분위기: 내추럴. 세이지 그린과 베이지, 꽃·식물 요소, 야외·스몰웨딩 느낌. 장식은 절제합니다.
  사진 자리는 회색 상자 + 설명 문구로 표시합니다.
- 날짜, 장소, 혜택 문구, 참가 업체는 실제 값이 없습니다. "[예시]"로 표시하고,
  수량·금액·할인율·"선착순 N명"·누적 신청자 수 같은 숫자는 만들지 마세요.

아래 디자인 토큰을 그대로 사용해 주세요 (CSS 변수):
--color-bg: #FBF8F3            페이지 배경
--color-surface: #FFFFFF       카드, 폼 패널
--color-secondary: #EFE7D8     베이지 섹션 배경
--color-text: #2B2A26          본문
--color-text-muted: #5E5A52    보조 문구 (14px 이상에만)
--color-primary: #4A6549       주 버튼 배경, 링크
--color-primary-hover: #3B523B 주 버튼 hover/active
--color-on-primary: #FFFFFF    주 버튼 글자
--color-accent-light: #A8B89A  장식 전용 (글자·입력칸 테두리에 쓰지 않음)
--color-border: #D9D1C3        장식용 구분선, 카드 테두리
--color-border-strong: #8C8578 입력칸·체크박스 테두리
--color-error: #B3261E         오류 (아이콘과 함께)
--color-success: #3D6B45       성공 (아이콘·글자와 함께)
--color-focus: #2E4A31         초점 링: 2px 실선, 2px 간격(offset)
글꼴: 본문·UI는 Pretendard (400 본문 / 500 라벨 / 600 버튼 / 700 강조),
      제목은 Noto Serif KR (600 섹션 제목 / 700 히어로 제목)
크기: 본문 16px·행간 1.7, 보조 14px 이상, 히어로 제목 PC 48px·모바일 32px, 섹션 제목 PC 32px·모바일 24px
모서리: 입력칸 8px, 카드 12px, 칩 999px / 간격 4px 단위 / 그림자는 카드에만 연하게 한 단계

기기:
PC(1440px) 먼저 디자인하고 같은 화면의 모바일(390px) 버전도 보여 주세요. 관리자 현황판은 PC만.

만들 화면:

1a) 기본 랜딩 (주소 "/")
   - 헤더: 로고, 섹션 이동 메뉴, 오른쪽에 고정된 "참가 신청하기" 버튼
   - 기본 히어로: 박람회 공통 소개 문구, "참가 신청하기" 버튼
   - 회차 카드 목록: 회차 이름·날짜·장소, "이 회차 신청" 버튼(누르면 신청 폼으로 스크롤하고 그 회차가 선택됨)
   - 참가 혜택 카드(PC 3~4열, 모바일 1열). 카드 구성: 아이콘(gift/ring/calendar/sparkle/leaf/ticket 중 하나),
     제목(20자 이내), 설명(60자 이내), 조건(선택, 40자 이내).
     예시: [예시] 방문 기념품 / [예시] 현장 계약 혜택(조건: 현장 계약 시) / [예시] 상담 우선 안내 / [예시] 경품 추첨
   - 참여 분야 소개: 웨딩홀, 스드메(스튜디오·드레스·메이크업), 혼수·가전, 예물, 허니문
   - 자주 묻는 질문: 펼치고 접는 목록
   - 신청 폼 섹션 (아래 2번)
   - 푸터: 운영자 정보 자리, 개인정보 처리방침 링크
   - 상태: 신청 가능한 회차가 하나도 없을 때의 화면

1b) 회차 랜딩 (주소 "/fairs/[회차]", 광고 링크용)
   - 회차 히어로: 회차 이름, 날짜, 장소를 크게. 기본 랜딩 히어로와 차이가 분명해야 합니다.
   - 혜택, 오시는 길, 자주 묻는 질문, 신청 폼(이 회차가 미리 선택됨)
   - 오시는 길: 주소, 안내 문구, "네이버 지도에서 보기"·"카카오맵에서 보기" 링크. 지도 이미지는 넣지 않습니다.
   - 상태: 종료되었거나 비공개인 회차에 들어왔을 때의 안내 화면

2) 참가 신청 폼 (랜딩 안의 섹션, 모달·별도 페이지 아님)
   필수 항목은 라벨 옆에 "필수" 글자로 표시합니다(색만으로 구분하지 않음).
   - 회차 [필수] 선택 목록. 신청 가능한 회차가 하나면 숨김
   - 이름 [필수]
   - 휴대폰 번호 [필수] 숫자 키패드, 010-0000-0000 형식 안내
   - 희망 방문 날짜 [필수] 선택한 회차의 개최일 중 고르는 선택지(달력 아님). 하루짜리 회차면 숨김
   - 희망 방문 시간대 [선택] [예시] 11:00–13:00 / 13:00–15:00 / 15:00–17:00 / 17:00–19:00
   - 예식 예정일 [선택] 날짜 선택 + "아직 미정" 체크
   - 예식 지역 [선택] 서울, 경기, 인천, 부산, 대구, 광주, 대전, 울산, 세종, 강원, 충북, 충남, 전북, 전남, 경북, 경남, 제주, 미정
   - 방문 인원(본인 포함) [선택] 1명 / 2명 / 3명 / 4명 이상, 기본 2명
   - 신랑/신부 구분 [선택]
   - 관심 분야 [선택] 복수 선택 칩: 웨딩홀, 스드메, 혼수·가전, 예물, 허니문, 기타
   - 개인정보 수집·이용 동의 [필수] "전문 보기" 펼침 + 체크박스(미리 체크하지 않음).
     전문은 회색 글자로 "[법률 검토 중인 동의문 자리]"만 표시
   - "신청하기" 버튼
   함께 보여 줄 상태: 항목 바로 아래 오류 문구(아이콘 포함), 제출 중(버튼 비활성 + 진행 표시),
   서버 오류 안내(입력값 유지)
   모바일: 화면 아래에 높이 56px 이상의 "참가 신청하기" 고정 버튼 바. 폼 섹션이 보이면 숨깁니다.
   마케팅 수신 동의, 회원가입, 결제는 넣지 않습니다.

3) 신청 완료 (주소 "/apply/complete")
   - 접수 확인 메시지, 신청 내용 요약(회차·날짜·시간대), 오시는 길, 처음으로 돌아가기
   - 요약 없이 기본 문구만 나오는 상태(새로고침했을 때)도 함께
   - 이번 버전은 문자·알림톡을 보내지 않습니다. "문자로 안내드려요" 같은 약속 문구를 쓰지 마세요.

4) 개인정보 처리방침
   - 긴 본문을 읽기 좋은 단순한 문서 레이아웃. 본문은 "[운영자 입력·법률 검토 필요]" 자리 표시로 둡니다.

5) 관리자 신청 현황판 (Payload CMS 관리자 화면에 추가되는 한 페이지, PC만)
   - 방문자 브랜드가 아니라 Payload 관리자 화면의 기본 스타일(중립적인 회색 계열, 밝은 화면)에 맞춥니다.
   - 상단: 회차 선택 드롭다운, "CSV 내려받기" 버튼
   - 요약 카드: 상태별 신청 수(신규 / 연락 완료 / 방문 확정 / 방문 완료 / 취소)와 중복 신청 수
   - 유입 경로: utm_source 기준 상위 항목(단순한 막대나 표)
   - 최근 신청 10건 표: 신청 시각, 이름, 휴대폰(가운데 가림, 예: 010-****-1234), 희망 방문일,
     상태 배지(글자 포함), 중복 표시. 행을 누르면 상세로 이동한다는 표시
   - 데이터가 없을 때의 빈 상태
   숫자는 0이나 [예시]로 두고 그럴듯한 실적을 만들지 마세요.

컴포넌트:
버튼(주/보조), 입력칸, 선택 목록, 체크박스, 칩, 아코디언, 카드, 하단 고정 버튼 바를
기본·hover·focus·오류·비활성 상태로 정리해 주세요. 입력칸 테두리는 --color-border-strong,
초점은 --color-focus 2px 링(2px 간격)을 씁니다.

제약:
- 접근성: WCAG 2.2 AA 목표. 모든 입력칸에 보이는 라벨, 키보드만으로 신청 완료 가능,
  초점 표시가 보이게, 상태를 색만으로 구분하지 않기.
- 한국어 문구는 해요체 존댓말로, 과장 광고 표현은 쓰지 않습니다.
- 구현은 Next.js + CSS Modules + CSS 변수로 합니다. 결과물은 Tailwind 클래스가 아니라
  CSS 변수와 컴포넌트별 CSS 형태로 주세요.

산출물:
- 화면 1a, 1b, 2, 3, 4(PC + 모바일)와 화면 5(PC)
- 위에 적은 상태별 화면들
- 컴포넌트 상태 정리표

검토 기준:
1. 첫 화면에서 "언제·어디서·어떻게 신청하는지"가 바로 보이는가
2. 모바일 하단 고정 버튼이 늘 보이고 폼 섹션에서는 사라지는가
3. 필수와 선택 항목이 글자로 구분되는가
4. 오류 문구가 해당 항목 바로 아래에 있는가
5. 지어낸 숫자나 약속 문구가 없는가
6. 기본 랜딩과 회차 랜딩의 히어로 차이가 분명한가
```

## 사용 방법

1. Claude Design에서 새 프로젝트를 만든다.
2. 위 코드 블록의 내용을 첫 메시지로 붙여 넣는다.
3. 결과를 보며 수정 요청을 이어서 보낸다.
4. 화면이 확정되면 Claude Design의 핸드오프 기능으로 구현 자료를 내보내고, `/moai plan` 단계에서 함께 참고한다.

## 적용 전 확인할 항목

남은 확인 사항(운영자 입력, 법률 검토, 구현 시 확인)은 [design-brief.md](design-brief.md)의 "남은 확인 사항" 표에 정리되어 있다.
