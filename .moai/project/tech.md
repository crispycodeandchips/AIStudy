# 기술 스택

## 시작 전 준비

1. **Node.js 업그레이드 (필수)**: 이 PC의 Node.js는 v14.16.1로, 현재 Next.js와 Payload 3.x의 최소 요구 버전보다 낮다. 현재 LTS로 업그레이드가 필요하다(Payload 3 최소 요구: Node 20.9 이상 — 설치 전 공식 문서로 재확인). npm도 함께 갱신된다.
2. Docker 실행 확인: PostgreSQL을 `docker-compose.yml`로 띄운다.
3. `.env.example`을 복사해 `.env`를 만들고 DB 접속 정보와 Payload 비밀 키를 채운다.

## 스택과 선택 이유

| 구성 요소 | 선택 | 이유 |
|-----------|------|------|
| 언어 | TypeScript | Payload 컬렉션 정의에서 타입이 생성되어, 신청 데이터 구조를 화면·API·테스트가 일관되게 공유한다. |
| 웹 프레임워크 | Next.js (App Router) | 사용자 지정. 랜딩페이지 렌더링과 서버 측 신청 처리를 한 앱에서 다룬다. |
| CMS / 관리자 화면 | Payload CMS 3.x | 사용자 지정. Next.js 앱 안에서 동작해 별도 서버가 필요 없고, 신청자 목록·검색·상태 관리 화면과 인증을 기본 제공한다. |
| DB 어댑터 | `@payloadcms/db-postgres` | PostgreSQL 연결용 공식 어댑터. |
| 데이터베이스 | PostgreSQL (Docker) | 사용자 지정. 로컬은 Docker로 실행하고, 운영 DB는 배포처와 함께 결정한다. |

| 스타일 | CSS Modules + 전역 CSS 변수 토큰 파일 | Tailwind는 쓰지 않는다. 토큰 파일을 방문자 레이아웃에서만 불러와 Payload 관리자 화면 스타일과 섞이지 않게 하고, Claude Design 결과를 CSS 변수와 컴포넌트별 CSS 형태로 그대로 옮기기 위해서다. 관리자 현황판은 Payload 관리자 화면 스타일을 따른다. |
| 글꼴 | Pretendard(본문·UI, `next/font/local` 자체 호스팅), Noto Serif KR(제목, `next/font/google`으로 빌드 시 받아 자체 호스팅) | 두 글꼴 모두 SIL OFL. 라이선스 원문은 구현 시 확인한다. |

버전은 Payload 3 계열의 설치 시점 최신 안정 버전(create-payload-app 기준)을 사용한다.

## 보안과 개인정보

- **동의 필수와 버전 관리**: 개인정보 수집·이용에 동의하지 않으면 신청을 저장하지 않는다. 동의문은 버전을 붙여 관리하고, 동의 시각(`consentedAt`)과 동의한 버전(`consentVersion`)을 서버에서 기록한다.
- **제3자 제공 없음**: 수집한 정보는 참가 업체를 포함한 제3자에게 제공하지 않는다. 제공 계획이 생기면 별도 동의가 필요하므로 동의문과 폼을 다시 정한다.
- **관리자 전용 접근**: 신청 데이터의 조회·수정·삭제는 Payload 인증을 통과한 관리자만 할 수 있다. 방문자는 생성만 가능하다.
- **CSV 내보내기 제한**: 인증된 관리자만 실행할 수 있다. 파일은 Windows Excel에서 한글이 깨지지 않도록 UTF-8(BOM 포함)으로 생성한다. 관리자 표·현황판은 휴대폰 번호 가운데를 가리지만 CSV에는 전체 번호가 들어가므로, 내려받은 파일의 관리 책임은 운영자에게 있으며 운영 문서에 적는다.
- **서버 전용 필드와 서버 측 검증**: `status`, `memo`, `isDuplicate`, `consentedAt`, `consentVersion`은 방문자가 설정할 수 없고 서버에서만 설정한다(필드 단위 접근 제한). 입력값 검증, 동의 확인, 스팸 방지는 신청 폼뿐 아니라 Payload REST/GraphQL API를 포함한 모든 생성 경로에서 서버 측에 적용한다. 구현 방식은 `/moai plan`에서 정한다.
- **스팸 방지**: 숨김 입력칸(honeypot)과 신청 횟수 제한을 적용한다. 외부 서비스는 쓰지 않는다.
  - 참고: 배포처가 정해지지 않았으므로 횟수 제한 상태를 단일 프로세스 메모리에만 두면 서버리스·다중 인스턴스 환경에서 제한이 작동하지 않을 수 있다. 상태 저장 위치는 `/moai plan`에서 정한다.
- **비밀 값 관리**: DB 비밀번호, Payload 비밀 키 등은 저장소에 커밋하지 않고 `.env`로 관리한다. 저장소에는 `.env.example`만 둔다.
- **보관 기간**: 제안은 회차 종료일로부터 3개월이다 [법률 검토 필요]. 동의 문구 확정 전(늦어도 운영 시작 전) 확정한다. 자동 파기는 첫 버전 범위 밖이므로, 기간이 지나면 운영자가 Payload 관리자 화면에서 회차별로 걸러 한꺼번에 삭제한다. 이 일괄 삭제 절차는 구현 단계에서 확인하고 문서로 남긴다.

## 배포

배포처는 정해지지 않았다. 특정 호스팅에 묶이지 않도록 다음을 유지한다.

- DB 접속 정보와 설정은 환경 변수로만 주입한다.
- 이미지 저장소는 교체 가능한 구성으로 둔다(첫 버전은 로컬 저장).
- 특정 플랫폼 전용 기능에 의존하지 않는다.
- 첫 버전에서는 외부 유료 서비스를 사용하지 않는다.
