# Project Interview

인터뷰 일자: 2026-11-08
프로젝트 유형: 새 프로젝트 (소스 코드 없음)

## Stage A Round 1: Vision and Domain
Question: 무엇을 만드는가? (사용자 요청 원문에서 직접 제시)
Answer: Next.js + Payload CMS + PostgreSQL 환경으로 웨딩페어 랜딩페이지를 만든다. 방문자에게서 참가 신청을 받고, 관리자 페이지에서 수집된 신청 정보를 확인하고 관리한다. 결정하기 어려운 부분은 질문으로 확인해 달라는 요청이 함께 있었다.
Domain: wedding-fair-lead-capture (이벤트 랜딩페이지 + 신청자 관리)
Goal: 웨딩페어 방문 신청을 랜딩페이지에서 빠짐없이 받고, 관리자가 Payload 관리자 화면에서 신청자를 확인·분류·내보내기할 수 있다.

## Stage A Round 2: Technology and Constraints
Question: 기술 스택과 지켜야 할 조건은? / 사이트와 DB를 어디서 돌릴 계획인가?
Answer:
- 기술 스택: Next.js + Payload CMS + PostgreSQL (사용자 지정)
- 실행 환경: 개발은 본인 Windows PC에서, PostgreSQL은 Docker로 실행. 배포처는 나중에 결정.
- 개인정보 보관 기간: 지금은 정하지 않음 (운영 전 반드시 결정해야 할 항목)
Constraints:
- 개인정보(이름·휴대폰 등)를 수집하므로 개인정보 수집·이용 동의를 필수로 받는다.
- 배포처가 정해지지 않았으므로 특정 호스팅에 묶이지 않는 구성을 유지한다.
- 개발 환경은 Windows. 확인된 도구: Node.js v14.16.1, npm 6.14.12, Docker 29.9.2. 현재 Node 버전은 Next.js·Payload의 최소 요구 버전보다 낮아 업그레이드가 필요하다.
- 첫 버전에는 외부 유료 서비스(문자·메일 발송 등)를 쓰지 않는다.

## Stage A Round 3: Scope and Boundaries
Question: 신청 폼 항목, 박람회 구조, 관리 기능, 알림, 콘텐츠 수정 방식, 인원 제한은?
Answer:
- 신청 폼: 이름, 휴대폰(기본) + 예식 예정일·예식 지역, 희망 방문 날짜·시간대, 동반 인원·신랑/신부 구분, 관심 분야(웨딩홀·스드메·혼수·허니문 등, 복수 선택), 개인정보 수집·이용 동의(기본)
- 박람회 구조: 관리자가 여러 회차(날짜·장소)를 등록하고, 신청자는 회차별로 묶인다.
- 관리 기능: 목록·검색·상세 보기(기본), 상태 관리(신규 → 연락 완료 → 방문 확정 → 방문 완료 / 취소), 상담 메모, 엑셀(CSV) 내려받기, 유입 경로(UTM) 기록
- 알림: 첫 버전에는 없음. 관리자 화면에서만 확인. 알림(관리자 이메일, 신청자 문자·알림톡)은 후속 과제.
- 랜딩페이지 콘텐츠: 메인 문구, 배너 이미지, 참가 혜택, FAQ를 관리자 화면에서 직접 수정한다.
- 인원 제한: 없음. 방문 시간대는 '희망' 정보로만 받는다.
Scope:
- 범위 안: 회차별 랜딩페이지, 신청 폼과 저장, Payload 관리자 화면에서의 신청자·회차·랜딩 콘텐츠 관리, CSV 내보내기, UTM 기록, 중복 신청 표시, 스팸 방지(숨김 입력칸 + 신청 횟수 제한)
- 범위 밖(첫 버전): 알림 발송, 시간대 정원 관리, 신청자 회원가입·로그인, 결제, 개인정보 자동 파기, 배포 자동화

## Stage B Round 4: Verification, Surfaces, and Sharing
Verification: 자동 테스트 + 브라우저 테스트. Vitest로 입력값 검증·저장 로직을, Playwright로 "랜딩페이지에서 신청 → 관리자 화면에서 확인" 흐름을 확인한다.
UI surface: has-ui
External systems: PostgreSQL (Docker, 로컬 개발)
Team sharing: solo (관리자 계정을 본인 혼자 쓴다는 답변에서 개발도 1인으로 판단, 확인 화면에서 이의 없음)

## 질문 없이 정한 기본값 (확인 화면에서 승인됨)
- 관리자 계정: 1개(본인). 역할 구분 없음.
- 중복 신청: 같은 회차 + 같은 휴대폰 번호로 다시 신청하면 막지 않고 "중복" 표시만 한다.
- 스팸 방지: 외부 서비스 없이 숨김 입력칸(honeypot)과 신청 횟수 제한으로 막는다.
