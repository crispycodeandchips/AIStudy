# 제품 개요 — 웨딩페어 랜딩 & 신청자 관리 (가칭)

## 개요

웨딩페어 방문 신청을 받는 랜딩페이지와, 수집된 신청 정보를 관리자 화면에서 확인·분류·내보내는 신청자 관리 기능으로 이루어진 웹 애플리케이션이다. Next.js, Payload CMS, PostgreSQL로 구성한다.

- 도메인: `wedding-fair-lead-capture` (이벤트 랜딩페이지 + 신청자 관리)
- 목표: 방문 신청을 랜딩페이지에서 빠짐없이 받고, 관리자가 Payload 관리자 화면에서 신청자를 확인·분류·내보낼 수 있게 한다.

## 대상 사용자

| 사용자 | 설명 |
|--------|------|
| 방문자 | 웨딩페어 방문을 고려하는 예비 신랑신부. 회원가입 없이 신청한다. |
| 관리자 | 운영자 1인. Payload 관리자 계정 1개를 사용하며 역할 구분은 없다. |

## 핵심 기능

### 방문자
- 기본 랜딩(`/`): 박람회 전체를 알리고 회차를 고르게 한다. 공통 히어로, 회차 카드 목록, 참가 혜택, 참여 분야, FAQ, 신청 폼 섹션을 보여 준다.
- 회차 랜딩(`/fairs/[slug]`): 광고 유입용. 회차 히어로(이름·날짜·장소), 혜택(회차 값 우선), 오시는 길, FAQ, 신청 폼(회차 미리 선택)을 보여 준다.
- 참가 신청 폼: 랜딩 안 `#apply` 섹션에 둔다(모달·별도 페이지 없음). 필수는 5개이고 나머지는 선택이다.

  | 항목 | 필수 | 입력 형태 |
  |------|------|-----------|
  | 회차 | 필수 | 선택 목록. 신청 가능한 회차가 하나면 자동 선택하고 숨김. 회차 랜딩에서는 미리 선택 |
  | 이름 | 필수 | 텍스트 |
  | 휴대폰 번호 | 필수 | 숫자 키패드, 010-0000-0000 형식 안내 |
  | 희망 방문 날짜 | 필수 | 선택한 회차의 개최일 중 선택. 하루짜리 회차는 자동 입력 후 숨김 |
  | 희망 방문 시간대 | 선택 | 회차별 시간대 목록 중 선택. 고르지 않으면 "미정". 희망 정보일 뿐 정원은 두지 않는다 |
  | 예식 예정일 | 선택 | 날짜 선택 + "아직 미정" 체크 |
  | 예식 지역 | 선택 | 시·도 17개 + 미정 |
  | 방문 인원(본인 포함) | 선택 | 1명 / 2명 / 3명 / 4명 이상, 기본값 2명 |
  | 신랑/신부 구분 | 선택 | 신랑 / 신부 |
  | 관심 분야 | 선택 | 복수 선택: 웨딩홀, 스드메, 혼수·가전, 예물, 허니문, 기타 |
  | 개인정보 수집·이용 동의 | 필수 | "전문 보기" 아코디언 + 체크박스(미리 체크하지 않음) |

- 회차별 시간대: 새 회차에 2시간 단위 기본 시간대 4개(11:00–13:00, 13:00–15:00, 15:00–17:00, 17:00–19:00)가 들어가고, 운영자가 회차마다 고칠 수 있다.
- 신청 완료 안내 화면: 신청 요약은 제출 직후에만 보여 주며, URL에 개인정보를 남기지 않는다.
- 오시는 길: 주소, 안내 문구, 네이버 지도·카카오맵 링크만 둔다(지도 임베드 없음).
- 개인정보 처리방침 페이지
- 유입 경로(UTM) 자동 기록

### 관리자
- 신청자 목록·검색·상세 보기
- 상태 관리: 신규 → 연락 완료 → 방문 확정 → 방문 완료 / 취소
- 상담 메모 작성
- CSV 내려받기
- 회차 등록·수정
- 랜딩 콘텐츠(메인 문구, 배너, 혜택, FAQ) 직접 수정
- 중복 신청 표시: 같은 회차와 같은 휴대폰 번호로 다시 신청하면 막지 않고 "중복"으로 표시한다.
- 휴대폰 번호 가림: 관리자 표와 현황판에서는 가운데를 가린다(예: 010-****-1234). CSV에는 전체 번호가 들어간다.
- 보관 기간 경과 후 파기: v1에서는 운영자가 Payload 관리자 화면에서 회차별로 걸러 직접 삭제한다(운영 절차).

### 공통
- 스팸 방지: 외부 서비스 없이 숨김 입력칸(honeypot)과 신청 횟수 제한을 적용한다.

## 사용자 흐름

### 방문자 흐름
1. 랜딩페이지 방문 (UTM 파라미터가 있으면 함께 기록)
2. 회차 확인 (날짜·장소, 혜택, FAQ)
3. 신청 폼 작성 및 개인정보 수집·이용 동의
4. 제출 → 신청 완료 화면

### 관리자 흐름
1. Payload 관리자 화면 로그인
2. 신청자 확인 (회차별 목록, 검색, 상세)
3. 상태 변경
4. 상담 메모 작성
5. CSV 내려받기

## 범위

### 첫 버전 범위 안
- 기본 랜딩과 회차별 랜딩페이지
- 신청 폼과 저장
- 개인정보 처리방침 페이지
- Payload 관리자 화면에서의 신청자·회차·랜딩 콘텐츠 관리
- 상태 관리와 상담 메모
- CSV 내보내기
- UTM 기록
- 중복 신청 표시
- 스팸 방지(honeypot + 신청 횟수 제한)

### 첫 버전 범위 밖
- 알림 발송(관리자 이메일, 신청자 문자·알림톡)
- 시간대별 정원 관리
- 신청자 회원가입·로그인
- 결제
- 개인정보 자동 파기
- 배포 자동화
- 외부 유료 서비스 사용
- 지도 임베드
- 참가 업체 목록
- 참가 업체를 포함한 제3자 제공

## Roadmap

아래 항목은 후속 과제 후보이며, 착수 여부와 순서는 정해지지 않았다.

- 알림 발송: 관리자 이메일, 신청자 문자·알림톡
- 시간대별 정원 관리
- 개인정보 보관 기간 적용과 자동 파기
- 배포 (호스팅·운영 DB·이미지 저장소 선정 포함)
- 관리자 역할 분리 (제안)
- CSV 내보내기 실행 기록(누가, 언제) 저장 (제안)
